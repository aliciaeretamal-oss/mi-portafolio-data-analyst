# Planificación del Portafolio — Alicia Retamal Durán

## 1. Repositorio elegido y justificación

**Repositorio: GitHub**, elegido por sobre Heroku, StackOverflow y YouTube:

- Control de versiones (historial de commits, ramas, colaboración).
- Estándar de facto de la industria de datos/TI — señal directa de empleabilidad.
- Renderiza nativamente README, notebooks (.ipynb) y scripts SQL/Python en el navegador.
- GitHub Pages gratuito para publicar un portafolio web estático desde el mismo repo.
- Fácil de enlazar desde LinkedIn y el CV, permitiendo revisar código real, no solo texto.

Heroku es una plataforma de *despliegue*, no de portafolio; StackOverflow mide reputación
en un foro, no autoría de proyectos; YouTube es un canal audiovisual sin versionado de código.

## 2. Ejemplo de portafolio de referencia

**Repositorio:** https://github.com/ehzl1234/refinery-anomaly-detection
Detección de anomalías en refinería (temperatura, presión, caudal, vibración) con
Isolation Forest — 100% Python, temática oil & gas.

**Me gusta:**
1. README estructurado con badges, planteamiento del problema, tabla de rangos por sensor
   y métricas de desempeño del modelo (precisión, recall, F1).
2. Sección "Domain Expertise" que conecta la experiencia real del autor con el proyecto.

**Perfectible:**
1. No tiene demo desplegada (solo instrucciones para correr localmente).
2. Datos de contacto mínimos (sin LinkedIn ni correo).

## 3. Buenas prácticas a aplicar en mi propio portafolio

- README completo por proyecto (objetivo, metodología, resultados, tecnologías usadas).
- Estructura de carpetas y nomenclatura de archivos consistente.
- Código comentado y legible.
- Datasets reales o realistas del rubro objetivo, sin información confidencial ni propietaria.
- Buenas prácticas de Git: commits descriptivos, `.gitignore`, ramas para features.
- Evidencia visual: gráficos, dashboards, capturas de pantalla.
- Perfil y bio completos, con foto y datos de contacto.
- Actualizaciones regulares y proyectos fijados (pinned) con los más representativos.
- Incluir licencia y `requirements.txt` en proyectos de código.
